# 动态抑郁状态建模与交互生成模块

## 1. 研究目标与模块边界

### 1.1 赛博小镇中的抑郁状态观察需求

- 说明静态人设难以呈现抑郁相关体验在不同事件、关系和对话轮次中的变化。
- 明确模块目标：使 agent 在小镇日常互动中呈现可追踪、可解释且连续的主诉、情绪与表达差异。

### 1.2 模块的功能定位

- 定位为连接角色基础人设、环境事件与语言生成模型的运行时状态层。
- 区分两类输出：面向语言模型的动态提示词，以及面向观察、存档和评估的结构化状态快照。

### 1.3 适用范围、非诊断声明与安全边界

- 说明该模块模拟的是抑郁相关表现和求助过程，不承担疾病诊断、风险判定或真实治疗决策。
- 规定危机表述、强烈自伤风险和现实医疗建议等情形须由独立安全机制或人工专业人员处理。

## 2. 总体架构与运行流程

### 2.1 模块组成与职责划分

- `DepressionSimulationEngine` 作为编排器，协调会话上下文、主诉图、情绪推断、记忆接口和提示词构建。
- `ComplaintGraphManager`、`EmotionInferencer`、与 `DynamicPromptBuilder` 的输入输出关系。

### 2.2 一轮交互的状态更新闭环

- 描述“事件/对话输入 → 上下文结构化 → 主诉节点评估 → 状态提交 → 情绪推断 → 动态提示词生成”的处理顺序。

## 3. 基于主诉图的长期抑郁状态建模

### 3.1 主诉节点的表示结构

- 以节点的主诉概述、核心信念、叙事焦点、表达风格和情绪向量共同刻画一个阶段性状态。
- 说明 `advance_signals`、`hold_signals`、`next_candidates` 与终止节点如何表达状态持续和可能的演变方向。

### 3.2 局部图规划与分支生成

- 说明初始节点由角色配置给出，LLM 在当前节点附近补充有限数量的候选子分支。
- 介绍局部窗口、短 ID 索引和分支修复对重复节点、无效边和上下文膨胀的约束。

### 3.3 状态迁移的评估与提交机制

- 说明迁移判断以角色本轮表达、对方话语和会话场景为依据，输出 `hold` 或 `advance` 等可审计结果。
- 讨论保守迁移和历史记录如何避免角色在相邻轮次中出现不合理跳变。

## 4. 情境化会话理解与社会关系调节

### 4.1 场景、关系与互动类型编码

- 编码地点、时段、互动对象、关系类型和互动类型，使同一主诉在工作、家庭、朋友或治疗场景中呈现不同表现。
- 将治疗对话作为一种专业支持场景，与普通社交事件保持可区分的上下文标记。

### 4.2 运行时事件与外部情境证据

- 介绍反思、环境事件等非对话输入如何以统一事件载荷进入状态更新管线。

## 5. 瞬时情绪与抑郁式表达生成

### 5.1 多维情绪向量与关系修饰

- 使用情绪正负向、唤起、防御、羞耻、无望和信任等连续维度描述当前节点的情感底色。
- 说明关系修饰器如何在治疗师、朋友、家人等对象面前调整信任、防御和自我袒露程度。

### 5.2 情绪连续性与受限波动

- 结合当前节点、会话线索和上一轮情绪，计算本轮强度、袒露程度与防御性。
- 介绍波动上限、稳定扰动和数值裁剪机制，确保变化小幅、可逆且不脱离长期主诉状态。

## 6. 实验设计与评估指标

### 6.1 抑郁 agent 表现真实性评估

- 从状态连续性、情境一致性、关系差异性、主诉可解释性和语言风格稳定性等维度进行评估。
- 结合专家评审、量表化标注和轨迹案例分析，避免仅以语言流畅度衡量真实性。

### 6.2 消融实验与可复现性分析

- 对比移除主诉图、关系修饰、情绪连续性约束或图窗口限制后的行为差异。
- 报告角色配置、提示词版本、随机性控制、状态快照与评审协议，保证实验可复现、可审计。

# 动态抑郁模块主诉链化重构设计方案

> 设计目标：彻底移除“旧状态机 / 粗粒度抑郁状态 / 压力-触发词驱动”思路，改为**完全由主诉链驱动**的人设动态系统。  
> 审阅对象：`modules/depression/*` 与 Agent 侧抑郁配置文件  
> 设计日期：2026-05-13

---

## 1. 重构目标

本次重构的总体原则只有一句话：

> **不再问“角色当前处于什么抑郁等级”，只问“角色当前走到主诉链的哪一个阶段、正在以什么方式组织和表达痛苦”。**

因此，本轮设计必须满足以下约束：

1. **`state_machine.py` 不再保留旧状态机语义**
   - 删除 `DepressionState`
   - 删除 coarse-grained / severity / crisis 之类旧投影概念
   - 删除“从阶段反推旧状态”的逻辑
   - 只保留“主诉链推进器”语义

2. **`context_analyzer.py` 不再做压力分、社交压力分、触发词检测**
   - 不再以“环境压力/触发词”驱动阶段变化
   - 改为“当前会话上下文整理器”
   - 为主诉链匹配、偏差选择、情绪推理服务

3. **认知偏差不再由粗粒度状态决定**
   - 不再存在 `severe_episode / mild_episode / remission ...`
   - 认知偏差直接由**当前主诉节点 + 会话内容 + 对话对象关系等**共同决定

4. **`memory_system.py` 暂时只保留接口**
   - 不做触发词激活
   - 不做压力阈值判断
   - 当前版本作为空实现/占位扩展点

5. **`emotion_inferencer.py` 改为主诉链驱动**
   - 根据当前主诉节点
   - 当前会话内容
   - 对话对象
   - 历史上一轮瞬时情绪
   推断角色本轮说话时的情绪风格

6. **所有动态抑郁配置，统一进入 Agent 私有抑郁档案**
   - 配置文件位置示例：  
     `/home/zbzhao/CODE/generative_agents/frontend/static/assets/village/agents/卡布达/depression_config.json`
   - 不再鼓励把动态抑郁逻辑碎片化放在 `agent.json` 或全局 intervention 配置里

---

## 2. 重构后的整体架构

新的模块关系建议如下：

```text
depression_config.json（每个 Agent 的私有抑郁档案）
        ↓
DepressionSimulationEngine
        ├─ ComplaintChainManager      （原 state_machine.py，现仅管理主诉链）
        ├─ SessionContextBuilder      （原 context_analyzer.py，现仅整理会话上下文）
        ├─ ComplaintBiasInjector      （原 bias_injector.py，现由主诉节点决定偏差）
        ├─ MemoryInterface            （原 memory_system.py，当前只保留接口）
        ├─ EmotionInferencer          （基于主诉链与当前会话推断瞬时情绪）
        └─ DynamicPromptBuilder       （基于主诉节点/情绪/偏差生成动态 Prompt）
```

### 核心变化

旧系统关注的是：

- 当前状态是不是更严重了
- 外部环境压力有多高
- 出现了哪些触发词

新系统关注的是：

- 当前主诉链节点是什么
- 本轮对话有没有实质触及该节点
- 角色此刻的表达组织方式是什么
- 对方身份会让角色更防御、更多说、还是更掩饰

## 4. 文件级重构方案

## 4.1 `state_machine.py` → 改造成纯主诉链管理器

### 建议改名

文件路径可以继续叫 `state_machine.py`，以减少 import 改动；  
但文件内部不再使用 “state machine” 这个心智模型。

建议类名改为：

- `ComplaintChainManager`

并在必要时让 `engine.py` 直接使用它。

### 明确删除

以下内容建议直接删除：

- `DepressionState`
- `STATE_SEVERITY`
- `_derive_legacy_state`
- `_contains_crisis_words`
- `_derive_state_characteristics` 中依赖旧状态投影的逻辑
- `force_transition(new_state)` 里对旧状态名的兼容处理
- 一切 `severe / moderate / mild / remission / crisis` 的判断

### 新职责

`ComplaintChainManager` 只做 4 件事：

1. 维护当前节点 `current_stage`
2. 维护当前规划链 `planned_chain`
3. 判断本轮会话是否“触及当前节点”
4. 根据主诉推进结果决定：
   - `hold`
   - `advance`
   - `replan`
   - `jump`（人工或 LLM 指定）

### 核心接口建议

```python
class ComplaintChainManager:
    def __init__(self, config: Dict, now_provider=None): ...

    def get_current_stage(self) -> Dict[str, Any]: ...
    def get_chain_snapshot(self) -> Dict[str, Any]: ...

    def evaluate_turn(
        self,
        session_context: Dict[str, Any],
        conversation_content: str,
        completion_func: Optional[Callable[[str], str]] = None,
        llm_cfg: Optional[Dict[str, Any]] = None,
    ) -> Dict[str, Any]:
        """
        return {
            "action": "hold|advance|replan|jump",
            "matched": bool,
            "match_confidence": float,
            "match_reason": str,
            "next_chain": [...],
            "current_stage": {...},
            "next_stage": {...} | None,
        }
        """

    def commit_turn(self, evaluation: Dict[str, Any]) -> Dict[str, Any]: ...
    def force_stage(self, stage_id: str, reason: str = "manual") -> None: ...
    def to_dict(self) -> Dict[str, Any]: ...
    @classmethod
    def from_dict(cls, payload: Dict[str, Any]) -> "ComplaintChainManager": ...
```

### 节点推进策略建议

每轮不再判断“状态更重还是更轻”，而是判断：

- 当前发言是否触及当前节点的核心主诉；
- 触及后，是应当：
  - 停留在该节点继续展开；
  - 推进到链中下一节点；
  - 重新规划后续主诉链。

### LLM 提示词建议

LLM 不再被要求输出：

- 当前粗粒度状态
- 严重等级
- 危机等级

而是只输出：

- 当前节点是否被触及
- 原因说明
- 当前会话后更合理的后续主诉节点链

## 4.3 `bias_injector.py` → 改造成主诉节点偏差注入器

### 问题来源

当前 `bias_injector.py` 的问题是：  
它仍然依赖旧的粗粒度状态：

- `severe_episode`
- `moderate_episode`
- `mild_episode`
- `remission`
- `crisis`

这与本次重构方向冲突。

### 新设计原则

认知偏差只由以下三类信息共同决定：

1. **当前主诉节点的 bias_profile**
2. **当前会话内容**
3. **对话对象关系与互动场景**

### 新接口建议

```python
class ComplaintBiasInjector:
    def inject_bias(
        self,
        current_stage: Dict[str, Any],
        session_context: Dict[str, Any],
        conversation_content: str = "",
    ) -> List[Dict[str, Any]]:
        ...
```

### 偏差选择逻辑建议

偏差选择不再依赖 severity，而改为：

1. 从当前节点读 `bias_profile.dominant`
2. 再根据当前会话内容判断是否加入 `secondary`
3. 根据关系修饰是否增强某种偏差表达，例如：
   - 面对家人更容易出现 `personalization`
   - 面对治疗师更容易出现 `should_statements` 或“说一点又缩回去”的表达

### 偏差输出建议

```json
[
  {
    "type": "all_or_nothing",
    "name": "全或无思维",
    "thought": "既然连工作都保不住，那我这个人整体就是失败的。",
    "source_stage_id": "job_loss_equals_self_failure",
    "confidence": 0.84
  }
]
```

### 保留部分

`COGNITIVE_BIASES` 这类模板库可以保留，但建议：

- 强模板与主诉节点绑定更紧；
- 支持在 `depression_config.json` 中为具体角色覆写模板。

## 4.4 `memory_system.py` → 只保留接口，不做激活逻辑

### 设计原则

按你的要求，这部分当前版本只保留接口，不做“触发—激活”机制。

### 建议类名

- `MemoryInterface`
或
- 保持 `TraumaMemorySystem` 类名，但内部实现为空壳

### 当前接口建议

```python
class TraumaMemorySystem:
    def __init__(self, config: Optional[Dict[str, Any]] = None): ...

    def prepare_memory_context(
        self,
        current_stage: Dict[str, Any],
        session_context: Dict[str, Any],
        conversation_content: str = "",
    ) -> List[Dict[str, Any]]:
        return []

    def commit_turn(self, *args, **kwargs) -> None:
        return None

    def get_memory_description(self) -> str:
        return "当前版本未启用记忆激活逻辑"

    def to_dict(self) -> Dict[str, Any]: ...
    @classmethod
    def from_dict(cls, payload: Dict[str, Any]) -> "TraumaMemorySystem": ...
```

### 为什么还要保留接口

因为后续如果想做更精细的设计，可以平滑扩展：

- 某些节点自带“既往叙事片段”
- 特定对象前会调用不同记忆片段
- 记忆不再靠 trigger，而靠主诉节点自身的叙事继承关系

但当前版本先不实现。

## 4.5 `emotion_inferencer.py` → 改造成主诉链驱动的瞬时情绪推理器

### 新定位

这个模块应当成为：

> **“当前节点如何在这次对话里转化成说话时的瞬时情绪风格”** 的专用推理器。

### 输入应包括

- 当前主诉节点
- 当前规划链窗口
- 当前会话内容
- 对话对象 / 关系
- 互动类型
- 上一轮瞬时情绪

### 输出建议

```json
{
  "label": "低落防御",
  "style": "说话偏慢，句子较短，会先否认严重性，再在追问下补一点细节。",
  "intensity": 0.74,
  "disclosure_level": 0.28,
  "defensiveness": 0.71,
  "volatility_note": "比上一轮更收紧一点，主要因为面对的是具有评估意味的对话场景。",
  "source": "llm"
}
```

### Fallback 规则建议

当没有 LLM 时，不再根据旧状态 fallback，而改成：

1. 读取当前节点 `emotion_vector`
2. 读取当前节点 `speaking_style`
3. 应用 `relation_modifiers`
4. 对上一轮情绪做小幅抖动

### Prompt 设计建议

LLM 的任务描述应明确强调：

- Emotion 不是长期病情结论
- Emotion 是“本轮说话时”的瞬时风格
- 只能围绕当前主诉节点做小幅波动
- 不能突然跨越成完全轻松或完全崩溃，除非当前节点本身就是那样

## 4.6 `prompt_builder.py` 也需要同步去状态机化

虽然你这次没有单独点名 `prompt_builder.py`，但如果前面全面主诉链化，这里必须同步修改。

### 必须删除

- `当前粗粒度状态：...`
- `重度/中度/轻度/缓解/危机` 这类文案
- 由旧状态投影出来的说明

### 新的 Prompt 分层建议

建议保留多层结构，但改为以下 5 层：

1. **基础人格层**
2. **当前主诉节点层**
3. **会话上下文层**
4. **认知偏差层**
5. **瞬时情绪与表达指导层**

### 当前主诉节点层建议文案

应当重点写清：

- 当前节点标题
- 当前节点核心信念
- 当前节点最容易围绕哪些问题组织表达
- 当前节点下的说话方式
- 若有后续节点窗口，则只允许“自然靠近”，不能跨越式跳转

## 4.7 `engine.py` 的职责调整

`DepressionSimulationEngine` 仍然可以保留，但它不再围绕“state machine”组织。

### 新初始化流程

引擎初始化时：

1. 读取 Agent 目录下的 `depression_config.json`
2. 解析其中的：
   - 主诉链配置
   - 偏差配置
   - 情绪推理配置
   - Prompt 配置
3. 构造：
   - `ComplaintChainManager`
   - `SessionContextBuilder`
   - `ComplaintBiasInjector`
   - `TraumaMemorySystem`
   - `EmotionInferencer`
   - `DynamicPromptBuilder`

### 新的 `commit_interaction()` 返回建议

```json
{
```

## 5. `depression_config.json` 的新配置方案

这是本轮重构里最重要的静态配置入口。

## 5.1 文件定位

每个 Agent 自己维护一个独立的抑郁档案，例如：

- `frontend/static/assets/village/agents/卡布达/depression_config.json`

### 设计原则

- `agent.json`：保留通用人物配置
- `depression_config.json`：保留动态抑郁主诉链配置

这样职责更清晰，也方便单独迭代抑郁模块。

---

## 6. 运行流程（新版本）

新的 `process_interaction / preview_interaction_prompt / commit_interaction` 建议按下列顺序执行：

```text
读取当前主诉档案
    ↓
SessionContextBuilder 整理当前会话上下文
    ↓
ComplaintChainManager 评估：
    - 本轮是否触及当前主诉节点
    - 是否继续停留 / 推进 / 重规划
    ↓
ComplaintBiasInjector 基于当前节点选择偏差
    ↓
TraumaMemorySystem.prepare_memory_context()  （当前为空）
    ↓
EmotionInferencer 推断本轮瞬时情绪风格
    ↓
DynamicPromptBuilder 生成动态 Prompt
    ↓
如 commit，则写入 runtime state
```

注意这个流程中**已经不存在任何“压力值驱动状态变化”的环节**。

## 9. 我建议这次重构时坚持的几个原则

## 9.1 不要再保留“兼容旧状态机”的中间层

如果这次还留着：

- `DepressionState`
- `current_state`
- old-to-new 映射

那么后续所有逻辑还会继续围绕旧范式打补丁。  
既然目标明确是“拥抱主诉链”，就应该一次切干净。

## 9.2 会话上下文只做“事实整理”，不要再做“心理评分器”

`context_analyzer.py` 最容易重新滑回旧逻辑。  
建议明确禁止：

- 压力分
- 触发词分
- 社交分
- 危机分

只保留：

- 谁和谁在说话
- 在什么场景
- 说了什么
- 这段话大致属于什么主诉主题/话语动作

## 9.3 偏差与情绪都要“贴节点走”

新的系统里：

- 节点决定偏差倾向
- 节点决定表达方式
- 节点决定基础情绪向量

这样才是一个真正统一的主诉链系统。
